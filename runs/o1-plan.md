# O1 测前预测（2026-11-09）

在执行两轮测量前保存。沿用 A3：MemoryMax=200M、MemorySwapMax=0、无 CPU 配额与额外绑核、report-max=0、每请求 8 MiB 保持 500 ms；负载为 Poisson、seed=1、10/20/30 请求每秒，每阶段 20 秒。压测器绑核 0-1，enrolld 使用主机全部 4 核。默认 GOGC=100，两轮只改变 GOMEMLIMIT（off 与 170MiB），不改服务源码或二进制。

预测：默认组可能像 A3 一样在 20 请求/秒阶段 OOM。170MiB 组将提前 GC，减少可回收垃圾占用，可能通过 20 请求/秒并把 OOM 推迟到 30 请求/秒；但无法保证存活。平均活跃报表内存为 40/80/120 MiB，突发在途数达到 22 时，仅报表活对象已为 176 MiB，再加运行时与其他开销就可能超过软目标甚至 200 MiB 硬上限。GC 不能回收仍在使用的报表。预计 170MiB 组 GC 次数、单位存活时间 GC CPU 开销会上升，尤其在高负载阶段。

连续运行默认组与 170MiB 组，分别存到 runs/o1-default 与 runs/o1-limit170。使用 scripts/run.sh 生成标准原始数据，额外每约 250 ms 保存 /metrics 原文，每 50 ms 保存 cgroup 内存计数，保存 systemd/内核退出证据。比较同一完整存活阶段的 GC 增量、GC CPU 估计与进程实际 CPU；死亡阶段只报告最后可见样本的下界及时间窗口，不将死亡后的零吞吐当成新阶段再次 OOM。运行后停止本实验实例。
